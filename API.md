# jingsao 对外 HTTP 接口一览

jingsao 的宿主半侧向 DSH 自己的 Web 服务注册了**一条前缀路由** `/jingsao-7341`，浏览器端、
桌面端、设置页与第三方插件全都访问同一份实现。本文只做**功能预览**（接口名 + 一句话），
完整契约——参数、响应体、字段含义、错误码与示例——见根目录的 [`openapi.yaml`](openapi.yaml)。

- **基址**：`http://127.0.0.1:<port>/jingsao-7341`，`<port>` 是 DSH Web 服务实际监听的端口
- **只监听 127.0.0.1，且没有鉴权**：任何能访问本机该端口的进程都能调用，请勿转发到公网

---

## 一、读状态

| 接口                            | 功能                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `GET /jingsao-7341/state`       | **轮询唯一数据源**：所有状态位都在这里；带 `?since=&timeout=` 可长轮询                                     |
| `GET /jingsao-7341/config`      | 读合并后的成品配置（内置默认 + 用户层，字段已填满）                                                        |
| `GET /jingsao-7341/config/meta` | 配置文件路径、日志文件路径、各类数据落盘位置、卸载该用哪个 profile                                         |
| `GET /jingsao-7341/models`      | 可用服务商与模型清单（与 DSH 自己的模型选择器同源）                                                        |
| `GET /jingsao-7341/chat?pet=`   | 读某只桌宠最近的对话记忆窗口；带 `?rounds=` 可指定本次读取的轮数（0–200，不传用配置的 `chatMemoryRounds`） |
| `GET /jingsao-7341/pose?pet=`   | 读**桌面端**宠物的实况（位置 + 朝向）；网页端用客户端服务 `jingsaoApi7341`，不走这条路                     |

## 二、占用锁

| 接口                                   | 功能                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /jingsao-7341/lock?pet=`         | **占用锁**：联动演出期间独占这只宠物（除持锁者外全静音）；取锁会先把它叫醒，占用期间不能再睡下；`lockId` 给了=续期、没给=新建，回 `lockId` + `expiresAt` |
| `POST /jingsao-7341/lock/release?pet=` | **释放占用**：`lockId`=持锁者收工 / `force`=用户接管（渲染端上报，第三方不用调）                                                                         |

**锁占用期间，桌宠完全静止**：它自己不动、也不弹气泡——余额、碎碎念、工作状态这些全都让路。

标了「（需锁）」的接口，第三方调用时**必须带上 `?lock=<lockId>`**。锁就是给第三方用的：带上它，
才能保证这段时间归你控制，不被别的插件、也不被桌宠自己的事件打断。没带 → `lock-required`；
编号不对 → `lock-lost`（附 `cause`：过期 / 已释放 / 被用户抢走）。

两条边界：

- **没有锁时**：不传 `?lock=` 一切照旧；传了 `?lock=` 说明你以为自己还持有 → 回 `lock-lost`，
  `cause` 告诉你锁是怎么没的（过期 / 已释放 / 被用户抢走）；
- **用户优先**：用户拖一下宠物、或把它隐藏 / 关闭，锁会立刻被撤掉。`/whisper`、`/balance`、`/chat`
  是用户自己点的入口（右键菜单 / 斜杠命令），占用期间照常可用。

## 三、让它说话（气泡）

| 接口                                   | 功能                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /jingsao-7341/whisper?pet=`      | 让桌宠**生成**一句碎碎念（走当前模型）；响应带 `text`，同时照旧写进气泡                                                                                                                                                                                                                                               |
| `POST /jingsao-7341/broadcast?pet=`    | **第三方投喂**（需锁）：把外部给定的文本写进气泡（不生成，只搬运）；第三方图片（`url` 地址）、时长、动画联动、是否念（`speak`，缺省不念）可选                                                                                                                                                                         |
| `POST /jingsao-7341/bubble/clear?pet=` | **清空气泡**（需锁）：提前收起说话气泡（只动气泡，不动动画）                                                                                                                                                                                                                                                          |
| `POST /jingsao-7341/chat?pet=`         | 对桌宠说一句话并生成回复，同时写入对话记忆；响应带 `text`，同时照旧写进气泡。可选 `attachment`（`mediaType` + base64）随本轮送一张图：图片**记进记忆**（存附件引用，不存本体），但只影响这一轮、不进气泡；不传时行为与旧版逐字一致。配置 `chatAnimationEnabled` 时回复可带 `[动作:名称]`，采纳后与 `/anim` 同链路点播 |
| `DELETE /jingsao-7341/chat?pet=`       | **删除对话记忆**：带 `?ts=`（可重复，取自 `GET /chat` 的 `messages[].ts`）只删这些轮——一轮两条共享 `ts`，成对删；不带 `ts` 清空整只。响应 `{ ok: true, removed }`，删空后不留空对象                                                                                                                                   |
| `GET /jingsao-7341/chat/memory`        | 列出**已删宠物**残留的对话历史（宠物删了但历史还在，`GET /chat` 读不到）；只给条数与最后时间                                                                                                                                                                                                                          |
| `DELETE /jingsao-7341/chat/memory`     | 一次清空这些残留历史                                                                                                                                                                                                                                                                                                  |
| `POST /jingsao-7341/balance`           | 立即刷新一次余额（可见效果同样是弹气泡 + 档位动画）；带 `?pet=`（需 `surface=`）时只让这只弹，不带则所有开启余额的宠物都弹                                                                                                                                                                                            |

## 四、让它做动作

| 接口                                      | 功能                                                                                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /jingsao-7341/anim?pet=`            | **点播动画**（需锁）：播池内名字（同右键「动作」菜单）或第三方自带的 `url`；`facing` 可选指定朝向（`left`/`right`，不传则不动朝向）；回 `playbackId`                           |
| `GET /jingsao-7341/playback/{id}`         | **播放回执**：查那次点播的真实状态；带 `?wait=&timeout=` 可挂起等待                                                                                                            |
| `POST /jingsao-7341/playback/{id}/report` | 渲染端上报播放状态（**内部通道**，第三方不用调）                                                                                                                               |
| `POST /jingsao-7341/pose/report?pet=`     | 桌面渲染端上报实况（**内部通道**，第三方不用调）                                                                                                                               |
| `POST /jingsao-7341/position?pet=`        | **位置控制**（需锁）：挪到归一化坐标，`mode` = 直接/弹簧/直线；不碰动画。额外回**夹取后**的 `x`/`y`                                                                            |
| `POST /jingsao-7341/throw?pet=`           | **原生抛掷**（需锁）：给桌宠一个初速度让它飞出去（`angle` 度、`power` 倍率）                                                                                                   |
| `POST /jingsao-7341/sleep?pet=`           | **让它睡下**：从 `animations.sleep` 里挑一整套（开始/循环/起来）写进 `pets.<id>.sleep`；睡着期间自动来源与手动触发一律拒绝（持锁时让路）；没配睡觉动画回 `no-sleep-animations` |
| `POST /jingsao-7341/wake?pet=`            | **叫醒**：播「起来」后回随机链；本来没睡也回 ok（幂等）                                                                                                                        |
| `POST /jingsao-7341/focus-session`        | **跳会话**：让页面切到指定会话；桌面端点会话气泡走这条                                                                                                                         |

## 五、改配置与重载

| 接口                             | 功能                                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `PUT /jingsao-7341/config`       | 保存用户层配置（白名单重建，用户手写的精调字段会保留）                                                                 |
| `POST /jingsao-7341/config`      | 用内置默认整份覆盖用户配置，即「恢复默认」                                                                             |
| `POST /jingsao-7341/pet-display` | **改单只宠物的显示位置**（`web` / `desktop` / `both` / `none`），只传 `{ id, display }`                                |

| `POST /jingsao-7341/reload`      | 重载桌面端（重启桌面宠物进程，按最新配置重建窗口）                                                                     |

## 六、第三方菜单项

| 接口                                         | 功能                                                                                                                                               |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /jingsao-7341/menu/item`               | **注册菜单项**（该 `owner` 的菜单项整体覆盖）：`{ owner, labels: ["弹弓","钓鱼"], target?: "web"\|"desktop"\|"both" }`，`target` 不写 = 两端都显示 |
| `DELETE /jingsao-7341/menu/item?owner=`      | **清除菜单项**（该 `owner` 的全部项，幂等）：回 `{ ok: true, removed: 2 }`                                                                         |
| `GET /jingsao-7341/menu/events?owner=&wait=` | **查询触发**（读取即清空，`wait` = 长轮询毫秒数）：回 `{ 弹弓: "main", 钓鱼: null }`                                                               |
| `POST /jingsao-7341/menu/click`              | 渲染端上报点击（**内部通道**，第三方不用调）                                                                                                       |

第三方菜单项统一收在右键菜单的**「更多」**下。`label` 在全部第三方项里唯一时直接平铺
（`更多 / 弹弓`）；`label` 重名时，每个 `owner` 在「更多」下各占一个子菜单（`更多 / owner / label`），
靠它区分同名项。宿主自己的菜单项固定，不参与重名判定。

## 十、C 盘清理面板

| 接口                              | 功能                                                                                                |
| --------------------------------- | --------------------------------------------------------------------------------------------------- |
| `POST /jingsao-7341/clean/open`   | **在用户看得见的那只鲸鱼娘旁边打开清理面板**：去向规则见表下说明；成功回 `{ ok: true, target: 'web' | 'desktop' }` |
| `GET /jingsao-7341/clean/page`    | 桌面清理小窗加载的独立页（HTML 壳：深浅两套配色、面板样式、自绘标题栏）                             |
| `GET /jingsao-7341/clean/page.js` | 独立页的面板脚本（包内 `lib/clean-page.js`，与网页同一份面板）；产物缺失回 `404`                    |

去向规则（`POST /clean/open` 与 AI 的「打开清理面板」工具共用；右键菜单不走这里，在哪一端右键就在哪一端弹）：

1. 网页在线且页面可见、并且有宠物在网页端显示（`display` 为 `web` / `both`）→ 网页浮层（`target: web`）；
2. 否则桌面 Helper 在线、并且有宠物在桌面显示（`desktop` / `both`）→ 桌面小窗，贴着那只桌面鲸鱼娘（`target: desktop`）；
3. 否则网页在线 → 网页浮层（兜底：用户切回 DSH 时能看到；宠物全部收起时浮层顶上有「叫她回来」）；
4. 否则宠物全部收起 → `pet-hidden`；两端都不在线 → `surface-offline`。

「在线 / 可见」按 `GET /state` 的轮询判断：插件自己的网页轮询带 `?surface=web&visible=0|1`（`visible` 取
`document.visibilityState === 'visible'`，DSH 窗口最小化或被切走时为 0），桌面 Helper 带 `?surface=desktop`。
15 秒内来过就算在线；「页面可见」只认最近约 3 秒内上报的 `visible=1`，过期按看不见处理（不带 `visible` 的老页面按可见处理）。
第三方轮询不要带这两个参数。打开信号写在 `sections.clean`（`{ open, target }`），只在 15 秒内有效。

面板里的其它 `/clean/*` 是面板自己用的内部通道（扫描 `scan`、立即清理 `run`、上个版本暂存区遗留数据的处理 `legacy`、
用系统方式清理 `system-action`、搬家与搬回、取消等）：清理直接删除，不进回收站、不进暂存区，删除前逐个复核文件身份；
需要管理员权限的系统规则整批提权一次（UAC）。所有清理动作只能由用户在面板里点，对话里的 AI 只有「只读扫描」和「打开面板」两个工具。

## state 详解

`GET /state` 是所有状态位的唯一出口，结构固定：

```jsonc
{
  "counter": 1755000000007,   // 整份 S 的版本号 = 最后一次写入的编号（顶层，不是叶子）
  "sections": {               // 全局段：所有端共享一份
    "balance": {…}, "workStatus": {…}, "notify": {…}, "config": {…}, "menu": {…}, "focusSession": {…}, "clean": {…}
  },
  "pets": {                   // 每只宠物各自一份；键是宠物 id（可含点号，勿切分）
    "main": { "say": {…}, "anim": {…}, "position": {…}, "throw": {…}, "lock": {…}, "sleep": {…} }
  }
}
```

每个 `{…}` 是一个叶子 `{ counter, data }`：**`counter` 变了就表示它更新了**（唯一判据）。

**长轮询**：`?since=<上次的顶层 counter>&timeout=<ms>`（成对必填，上限 10s）。有字段改变就
**立刻返回**，否则一直挂到 `timeout` 到点；返回体与不带参数时一样。

**前端在每个需要的地方各存一份 `counter`**：首拉只记基线不渲染，之后一样就不渲染、不一样就
渲染并更新——据此判断变了没有、要不要触发。

**分段点播**：`pets.<id>.anim` 除 `name` / `url` / `playbackId` / `facing` 外，宿主自己驱动清理动画时还会写
`next`（第一段播完接着播的那段）与 `loop: true`（最后一段一直循环，直到收到下一条点播指令为止），
例如清理开始 `{ name: '清理-吸入-开始', next: '清理-吸入-循环-中', loop: true }`、清理成功
`{ name: '清理-打嗝', next: '清理-推容量条-大' }`。两端渲染器共用 shared/state 的 `startAnimChain` /
`advanceAnimChain` 口径；`POST /anim` 不接受这两个字段，老渲染端忽略它们（只播第一段）。

## 独立模式（不打开 DSH）

不启动 DSH 时，同一份 `/jingsao-7341` 契约由本机服务提供，另外多出三个**挂在服务根上**的端点
（**不在 `/jingsao-7341` 前缀下**）：

| 接口                   | 功能                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------- |
| `GET /`、`GET /health` | 服务与插件信息：名称、插件根与版本、监听端口、已运行秒数                                |
| `POST /shutdown`       | 优雅停机：释放插件注册的 effect（停止桌面助手、清掉周期定时器）后关闭服务，进程退出码 0 |

`/jingsao-7341` 下的端点形状不变，但三个依赖 DSH 的接口**明确降级**（结构化失败，不假装成功）：
`POST /whisper`、`POST /chat` 回 `reason: 'provider-missing'`，`POST /balance` 回 `reason: 'unsupported'`。

## 收起与叫回鲸鱼娘

所有入口使用同一组动作接口，业务失败返回 HTTP 200 与 `{ok:false, reason, message}`，成功返回 `{ok:true}`。JSON 语法错误返回 400，方法错误返回 405。

| POST 路径                    | 请求体               | 行为                                                                                                                                     |
| ---------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `/jingsao-7341/pet-hide`     | 可选 `{id, surface}` | id 缺省为全部宠物，surface 可选 web、desktop、both，默认 both。持久化原 display 后随机播放所属条目的 hideTexts，约 1500ms 后收起目标端。 |
| `/jingsao-7341/pet-restore`  | 可选 `{id}`          | 恢复有收起记录或 display 为 none 的宠物。优先原 display，无记录回到 web，已恢复记录删除。                                                |
| `/jingsao-7341/desktop-exit` | 空对象或无请求体     | 所有 desktop 变 none、both 变 web，保存原 display，告别后停止 Helper 与托盘。取消本次运行的托盘常驻资格。                                |

收起记录保存在插件数据目录 `$DSH_HOME/jingsao/hidden-pets.json`，格式为 `{stateVersion:1,pets:{宠物id:原display}}`。连续从两端收起保留首次显示位置。缺失或损坏的记录文件按空记录处理。配置写入与恢复共用串行队列，批量操作部分失败时保留未恢复记录供重试。

`/jingsao` 与 `/jingsao 出来` 调用恢复接口，`/jingsao 收起` 收起全部宠物的两端显示。清理面板在全部宠物 display 为 none 时显示「鲸鱼娘收起来了」与「叫她回来」按钮。托盘勾选行为沿用原显示位置切换。

DSH 托盘提供「退出桌面鲸鱼娘」。之后 `/jingsao 出来` 恢复桌面显示，或用户通过「显示位置」送回桌面时，Helper 可以重新启动。独立模式保留「退出」的宿主退出行为。

`hideTexts` 为条目级非空字符串数组，每项须含非空白字符。老配置缺少此字段时使用 `assets/config.jsonc` 内置台词。
